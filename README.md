# SYSTEM Player Dashboard — MVP

Тёмный RPG-трекер привычек на Next.js 14, React, TypeScript и Tailwind CSS. После настройки таблицы Supabase игровой прогресс сохраняется в облаке отдельно для каждого аккаунта; локальное сохранение можно перенести с подтверждением.

## Запуск приложения

Нужен Node.js 18.17 или новее.

```bash
pnpm install
pnpm dev
```

Откройте http://localhost:3000. При первом запуске настройте Supabase по инструкции ниже.

## Возможности

- Профиль игрока, уровень и шкала опыта. Опыт для следующего уровня: `100 + (уровень − 1) × 50`.
- Характеристики STR / INT / END / DISC; за каждый уровень начисляется 3 очка характеристик.
- Ежедневные квесты по часовому поясу UTC+5; новый набор появляется каждую полночь.
- Сложность заданий и награды повышаются вместе с уровнем игрока.
- До трёх случайных секретных заданий открываются после выполнения всех текущих квестов за день.
- Создание собственных заданий, награды EXP и Gold.
- Магазин наград с оплатой Gold.
- Журнал событий и карта активности за 28 дней.
- Облачное сохранение прогресса по аккаунту Supabase и локальная резервная копия.
- Регистрация и вход по email и паролю, подтверждение email, сессия и защита панели входом.

## Ежедневные задания

- Новый день начинается в `00:00 UTC+5`; задания сбрасываются автоматически, пока страница открыта, и сверяются при загрузке.
- Сложность на новых заданиях зависит от текущего уровня. Длительность движения и фокуса, объём чтения и планирования постепенно растут с ограничениями; награды тоже увеличиваются. Цель по воде остаётся личной нормой, а её награда растёт с уровнем.
- После выполнения всех активных заданий открывается случайный секретный квест. Если выполнить его, может открыться следующий. За день открывается не больше трёх секретных квестов.
- Секретные задания подсвечены фиолетовым. Метка `LVL` показывает уровень сложности, на котором задание было выдано.

## Настройка Supabase Auth

1. **Создайте проект Supabase.** Зарегистрируйтесь на [supabase.com](https://supabase.com), нажмите **New project**, задайте имя, пароль базы данных и регион. Дождитесь готовности проекта.
2. **Скопируйте ключи.** В Supabase откройте **Connect** или **Project Settings → API Keys**. Скопируйте Project URL и публичный anon/publishable API key. Не используйте `service_role` или secret key в браузерных переменных `NEXT_PUBLIC_`.
3. **Создайте локальный файл переменных.** В папке приложения скопируйте `.env.example` в `.env.local` и вставьте свои значения:
   ```env
   NEXT_PUBLIC_SUPABASE_URL=https://ВАШ-ПРОЕКТ.supabase.co
   NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=ВАШ_ПУБЛИЧНЫЙ_КЛЮЧ
   ```
   Не отправляйте `.env.local` в GitHub. После изменения переменных перезапустите приложение.
4. **Разрешите адреса для подтверждения email.** В Supabase откройте **Authentication → URL Configuration**. Для разработки установите Site URL `http://localhost:3000` и добавьте этот адрес в Redirect URLs. Добавьте туда и адрес вашего сайта Vercel, например `https://ваш-сайт.vercel.app`. Для рабочего проекта укажите адрес Vercel как Site URL. Адреса Vercel Preview добавляйте, только если планируете тестировать на них вход и подтверждение почты.
5. **Проверьте локально.** Запустите `pnpm dev`, откройте http://localhost:3000/login и зарегистрируйте тестовый аккаунт. Если Supabase просит подтверждение, откройте письмо и перейдите по ссылке, затем войдите.
6. **Добавьте переменные в Vercel.** Откройте проект Vercel → **Settings → Environment Variables**. Добавьте `NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`, вставив значения из Supabase. Выберите Production (и Preview, если нужно), сохраните и заново разверните приложение.
7. **Проверьте рабочий сайт.** Зарегистрируйте тестовый аккаунт, подтвердите email, войдите, обновите закрытую страницу и выйдите через кнопку в верхней части панели.

### Восстановление пароля

На странице входа нажмите **«Забыли пароль?»**, введите email аккаунта и нажмите **«Отправить ссылку»**. Откройте письмо Supabase, перейдите по ссылке, задайте новый пароль длиной от 8 символов и нажмите **«Изменить пароль»**.

Чтобы ссылка сработала на локальном сайте и на Vercel, откройте Supabase → **Authentication → URL Configuration → Redirect URLs** и добавьте разрешённые адреса возврата: `http://localhost:3000/auth/callback` и `https://ВАШ-ДОМЕН-VERCEL/auth/callback`. Сохраните изменения. Используйте основной домен Production; если хотите сбрасывать пароль из Preview-развёртываний, добавьте соответствующие Preview URL отдельно. Письмо также может попасть в папку «Спам».

## Включение облачного сохранения и переноса старого прогресса

Код приложения теперь умеет загружать и сохранять игру в таблицу `player_progress`. Каждая запись привязана к ID текущего аккаунта. Доступ ограничен правилами Row Level Security (RLS), поэтому пользователь может читать и менять только свою запись.

1. В Supabase откройте **SQL Editor → New query**.
2. Откройте файл `supabase/player_progress.sql` в этой папке, скопируйте весь текст и вставьте его в окно SQL Editor.
3. Нажмите **Run**. Скрипт создаст таблицу, включит RLS, выдаст нужные права вошедшим пользователям и установит правила доступа. Его можно запустить повторно: политики будут пересозданы.
4. Отправьте обновлённые файлы проекта в подключённый GitHub-репозиторий и дождитесь нового развёртывания Vercel. Переменные Supabase уже те же, что используются для входа; новых переменных не требуется.
5. Войдите в приложение. Если в этом браузере найдено старое локальное сохранение, появится выбор **Перенести прогресс** или **Начать заново**. Перенос отправляет сохранение в аккаунт Supabase после нажатия кнопки. Исходный `localStorage` при этом не удаляется.
6. Проверьте другой браузер или устройство: после входа в тот же аккаунт должна загрузиться облачная игра. Отдельный аккаунт начинает собственное сохранение.

Если нажать **Начать заново**, локальный старый прогресс останется в браузере, а в облаке для этого аккаунта начнётся новая игра. Не очищайте данные сайта вручную, пока не убедитесь, что нужное сохранение перенесено.

## Примечания

- Сброс ежедневных заданий сейчас происходит при следующем открытии приложения после смены даты; штраф — 10 HP. Для надёжной серверной обработки понадобится база данных и серверный планировщик.
- `crypto.randomUUID()` работает в современных браузерах.
